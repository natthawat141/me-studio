# Architecture and backend boundary

## Decision
Start with a modular monolith: Next.js HTTP handlers → server services → repositories/providers. Keep video execution in a separate sandboxed worker, not in a request handler or browser. This avoids running several services before the domain is stable, while allowing workers to scale independently later.

2026-11-02 local-first update: the immediate target is the downloadable hackathon prototype, documented in [ADR 0004](decisions/0004-local-first-runtime.md). A separate Node CLI under scripts/local/ now renders reviewed HTML/audio into validated MP4, snapshots explicit input files and records per-render status under .studio/renders. It runs a fresh browser process/context, serves only listed local assets and blocks external page networking. It is **not** the sandboxed worker above, an arbitrary-code sandbox, a durable queue or a web execution API. Studio chat and application persistence remain unchanged. See [local setup/limitations](local-development.md).

Current public API code: src/app/api/health and src/app/api/catalog, src/server/config.ts, src/lib/provider-config.ts. An internal Pi harness and scoped SQLite memory/run store exist under src/server/agent and src/server/memory. A dormant native worker/Meta adapter composes them separately; current `/desktop` chat does not use that path, and no public chat HTTP endpoint or end-to-end live inference is verified. No tenant/application database or auth is implemented. UI/domain contracts must not import server modules. server-only guards configuration and the agent entry; public catalog is an explicit projection without keys/env names/URLs. See [ADR 0005](decisions/0005-agent-harness-memory.md), [harness boundaries](agent-harness.md) and [AI orientation](ai-guide.md).

## UI organization

Desktop V1 update (2026-11-03): `/desktop` composes `chat-sidebar`, `chat-composer`, `chat-search`, `chat-settings` and `chat-artifact-preview`. `use-chat-prototype` is a local scripted adapter using strict non-secret schemas in `src/lib/chat-prototype.ts`; it neither imports server modules nor calls the desktop bridge/provider APIs. A separate storage key preserves legacy browser/native project data. File bytes stay in memory by chat; sample messages persist filenames only. This is not an asset upload implementation. Provider metadata does not authorize a connection; API key input is disabled. Browser storage has no cross-tab transaction guarantee.

`layout/desktop-navigation` owns a shared window-wide header above `chat-workspace`, with conversation identity, sidebar/new-chat controls, one selected-file tab and Files access. The expanded history sidebar and compact desktop rail share the same callbacks/state. WorkspacePanel owns its independent file-tree visibility; hiding the tree changes layout while retaining the media element. Folder Projects now bind a stable ID and name to a user-selected native directory in an application-owned registry; chat records retain optional projectId. Selecting a Project activates its directory in the existing Files service. Moving a directory requires user relink and preserves the ID/chat association. Existing ungrouped chats remain intact. This does not grant AI execution rights.

Electron owns the native window and macOS sidebar vibrancy; a solid white main area masks the effect outside the sidebar. Existing runtime/renderer/IPC code remains on disk but is not used by the current chat frontend. Backend language/framework remains open for the later harness phase, including Python. See the current [frontend plan](plans/2026-11-03-chat-first-frontend.md).

The Files panel is a separate real native integration: `use-workspace-files` → `services/workspace-files` → narrow `meStudioFiles` preload methods → owned-main-frame IPC → `desktop/workspace-files.mjs`. Only the native folder picker grants a root; renderer requests use opaque entry IDs, never arbitrary paths. Lazy listings skip hidden files/symlinks, resolve containment again on access and cap directory results at 500 and issued entries at 10,000. Text reads are bounded to 256 KB and rendered as escaped text. Media streams through `studio-file` with byte-range/HEAD support registered on the actual persistent Electron session; it does not buffer full videos. The service is read-only and is not a generated-code execution sandbox. Closing the panel retains the current folder state; quitting the app clears its grant. No file watcher, filesystem editing, terminal or general browser is introduced. References: [Electron session-specific protocols](https://www.electronjs.org/docs/latest/api/protocol), [directory picker](https://www.electronjs.org/docs/latest/api/dialog), [context isolation](https://www.electronjs.org/docs/latest/tutorial/context-isolation), reviewed 2026-11-03.

Project creation separates native folder selection from committing the registry entry. The main process retains the selected path and returns an opaque selection ID plus folder name; the Create request accepts that ID, not a renderer-supplied path. Cancelling the picker leaves any previous selection intact, and only successful creation consumes the selection. Reopening a saved Project revalidates its registered directory.

App Router pages remain route entrypoints; their client screens live under `src/components/studio`, `projects`, `library`, `settings`, `auth` and `preview`. Shared application UI lives under `layout`, `chat` and `media`; installed primitives remain under `ui`. Dedicated component styles stay beside their owner. See the [code map](../README.md#code-map) for folder responsibilities. This organization preserves the existing URLs, component interfaces and browser persistence; it does not change the current mock/provider boundaries or extract the studio's orchestration into new services.

## Target domain (planned)
User, Workspace, Membership(role), Project(workspaceId, revision), Conversation(projectId), Message(conversationId, asset references), Asset(workspaceId, provenance, storageKey, media type), StoryboardVersion, Generation(input snapshot, model/voice/output config), Quote(expiresAt, inputHash), Approval, Job(status, attempt), ArtifactVersion, UsageLedger(idempotency key).
Every server operation derives actor/workspace membership from verified session; client IDs are lookup keys, not authority. Asset access, signed URLs, downloads and worker callbacks require equivalent ownership checks.

## Data/storage
Postgres is the proposed transactional source of truth for SaaS metadata, jobs, quotes and ledger. Object storage holds binaries; queue/workers own execution. Choose auth provider and hosting in a recorded ADR before provisioning. Self-hosting uses the same API semantics; SQLite is not promised without a separate tested repository implementation.
Legacy localStorage/IndexedDB data remains on-device. Cloud migration must be explicit, exportable, resumable and preserve legacy IDs/provenance. Current revision checks detect stale snapshots but are not atomic across browser processes. Move local writes to one transactional IndexedDB repository before claiming multi-tab safety. IndexedDB blob deletion + localStorage changes are currently not a shared transaction.

## Providers
Current metadata registry: OpenRouter(chat), OpenAI(chat), Meta Model API(chat) and ElevenLabs(speech). Server env can specify a default chat model only from its configured lists and a separate speech voice ID. Requested standby config is OpenAI `gpt-6-luna`, Meta `muse-spark-1.3-contributor` and ElevenLabs `eleven_v3` with an example voice. See [research and readiness](model-research-2026-11-03.md), including Contributor data usage and the ElevenLabs 401 result. The dormant trusted Meta adapter accepts the Contributor route; it is not invoked by the desktop sample UI. OpenAI/speech generation adapters are not introduced. Configured means a key exists, not that it is verified/entitled. Browser catalog contains only safe metadata and allowed models. Adding a model does not grant permission to call it. Developer env credentials stay outside distributables and are not automatically loaded into the environment-isolated native runtime.
Never accept arbitrary upstream URLs or env names from public requests. Additional transports require a reviewed server adapter. Credentials are resolved server-side per deployment/owner; UI may store only preferences. SaaS defaults to operator keys; tenant BYOK is a later encrypted vault feature.

## API stages
Implemented GET /api/health: process liveness only, not auth/database/provider readiness.
Implemented GET /api/catalog: configured modes and operator-approved model metadata; no upstream calls or secrets.
Planned authenticated endpoints: session; project CRUD with revisions; assets upload/complete/download; chat turns + resumable events; voices/models; quote; approval; generation; job status/cancel; artifact revisions.
Paid endpoints must not be published before auth, ownership, input validation, rate limiting, budget checks and idempotency. Separate transport status from upstream/model errors. Unknown failure → actionable safe message with request ID; never echo provider response bodies/credentials.

## Job invariants
Proposed: draft → quoted → approved → queued → running → succeeded/failed/cancelled. State transitions, timeout/retry limits and cancellation are server enforced. Quote/approval binds to exact inputs; credit reservation and job enqueue require transactional consistency/outbox. Render output is validated before publishing. Generated code runs in isolated execution with resource/time/network limits and no service credentials. HTML preview uses an isolated sandbox/origin; preview success does not imply render success.
