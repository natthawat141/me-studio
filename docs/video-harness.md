# Conversational video harness

me studio is a creative collaborator. The user supplies intent and references; the agent discusses, clarifies consequential unknowns, suggests reasoned choices and executes when asked. There is no universal interview, forced approval wizard, default eight-second clip, fixed cast or preset background.

## Native configuration

The File menu, top navigation, Files header and Settings → AI providers can open `config.env` in the application userData directory. It is a private local file (0600), excluded from source and packaging. Existing credential-file import remains available on older preview UI; new native configuration reloads on focus, explicit refresh and before sending. Neither keys nor config contents are sent to the renderer. Presence of a key is not verified account access.

An in-app connection form accepts a new API key without reading an existing key back into the renderer. Unconfigured providers show a key-entry action; their model switches appear after saving. `OPENAI_API_KEY`, `OPENROUTER_API_KEY` and `META_API_KEY` enable their respective model groups. Native OpenAI defaults include GPT-6 Luna, GPT-6.1 Sol, GPT-6.1 Terra, GPT-6 Astra and GPT-6 Sol. Settings search/toggles persist enabled flags in the file. Only enabled models with a provider key appear in the composer. The selected provider/model travels through the trusted host to Python; fixed endpoints are not renderer-controlled. OpenRouter model IDs are explicitly added via `STUDIO_CHAT_MODELS`; model/tool support varies by provider. Native Meta also uses a fixed Responses endpoint; Muse Spark/Wonder IDs are seeded. Contributor rows state their data-training mode. Custom forms in legacy web routes are separate.

`STUDIO_DEFAULT_CHAT_PROVIDER`, `STUDIO_DEFAULT_CHAT_MODEL`, `STUDIO_OPENAI_MODELS`, `STUDIO_CHAT_MODELS`, `ELEVENLABS_API_KEY`, `STUDIO_SPEECH_VOICE_ID`, `STUDIO_SPEECH_MODEL`, `STUDIO_SPEECH_LANGUAGE` configure native operation. Model entries are `{id,label,enabled}`. The browser catalog has a separate schema; do not copy native enabled flags into legacy web env lists.

## Conversation and tools

- `/style`, `/voice`, `/preview`, `/skills` are discoverable by typing `/`. Arrows/Enter choose a command without sending it; IME/repeated Enter remain protected. Natural language is equally valid.
- `present_options` displays a contextual question and clickable choices. Users can select, mix or reject them in ordinary chat. Choosing a card preserves an existing text draft.
- `save_html_animation` creates original declarative HTML/CSS/inline SVG with CSS keyframe animations, then returns a real screenshot in chat. No fixed character, background, composition or duration is imposed. The model does not author executable JavaScript.
- `read_current_animation` exposes the latest draft or a numbered earlier version. Up to 20 versions are retained per conversation in the Project's internal skills directory. Choosing a previous direction must restore that version, rather than continuing the most recently generated comparison.
- `read_video_skills` loads bundled/project references and enabled status. `set_video_skill` changes project-specific skill preferences when requested. Skills do not grant tool/file permissions. Existing project overrides are preserved.
- Bundled references include `screen-recording`, added to existing Projects at their next production initialization without replacing custom skills. It distinguishes app-window recording from HTML capture/rendering. The product has no desktop recording tool; see the separate [trusted operator workflow](screen-recording.md). Enabling the guide does not enable OS capture.
- `synthesize_voice` uses the configured ElevenLabs voice/model/language. It refuses missing keys, missing narration and speech exceeding its cue; failures must not silently become narrated output.
- `list_audio_assets` lists actual attached audio handles and measured durations. `set_audio_track` selects one recording, its video offset and volume, or explicitly removes it. Selection persists across draft edits and restarts. The full recording must fit the timeline; oversized audio is rejected rather than silently cut. Existing narration requires no speech API call.
- `render_video` renders verified H.264/AAC MP4 locally. Up to three versioned render attempts per request; current creative limit is 300 seconds, 320–1280 even pixel dimensions and 24 fps. This is a technical bound, not an eight-second product default.
- `save_animation` and its two-character Canvas schema remain only as a legacy test/CLI compatibility path. They are excluded from the active native agent tool list.

The host parses HTML in an inert document and rejects active elements/handlers and external resources. A trusted seek implementation advances CSS animations. Chromium runs outside the privileged Electron UI with sandboxing, blocked networking and no downloads/service workers; the existing FFmpeg path snapshots explicit inputs. This is not a general shell/Python/JavaScript execution service.

Conversation can start in Default workspace without creating a Project. Folder Projects retain their scoped local output. Ordinary discussion creates no animation version directory. Only produced preview images and the final video are presented in chat; manifests/source/working notes remain in Files.

Local file actions: **Show in Finder** reveals the resolved chat/preview file. **Save a copy…** offers a direct Downloads copy or a native destination-folder picker; cancellation preserves the original. Copies never overwrite an existing file. The agent's `save_file_to_downloads` tool accepts only a generated ID from the current conversation and an optional plain filename with the same extension. The host supplies Downloads independently of model/renderer arguments. Duplicate names receive a numeric suffix; copies remain discoverable through `list_generated_files`. No unrestricted destination path or shell execution is exposed. Other folders use the native destination-folder picker. Copying HTML alone does not bundle its relative dependencies.

## Verification and limits

See [implementation evidence](plans/2026-11-03-creative-config.md). The Python demo now authors a typography-based HTML animation and renders a real three-second MP4 with an offline scripted provider. Creative smoke checks reject active/external HTML and restore a draft across requests before rendering. These checks do not measure creative quality or verify live provider entitlement. API keys remain local and provider error bodies remain private.

Native attachments are stored and viewed inline. Sending images/text enters the normal Python agent flow; the host resolves opaque scoped file IDs, downsizes images (up to 6, at most 250 KB each) and passes them privately as Responses input_image parts. Plain text is bounded to 30,000 characters in total. User image references and earlier audio handles are reattached on subsequent turns in that chat, without persisting base64 in transcripts. Trusted main-process audio grants stay private; model-visible handles include ID, filename and measured duration only. Uploaded MP3/WAV/M4A/OGG up to 25 MiB and 300 seconds are copied as bounded normalized PCM within per-chat state; originals remain unchanged. The selected recording is included in the rendered AAC track, retaining selection after reopening. Filename text alone is not an upload or a file grant. Old locally-only attachment messages can be resent explicitly. The selected model must support image input; unsupported models surface a send failure. Audio/video analysis, arbitrary imported-clip assembly, external image search, phoneme lip-sync, a multitrack editor, cloud sync and arbitrary generated-code execution remain unimplemented. The available tools must be described honestly by the agent.

## Response presentation

Assistant responses are stored as Markdown and rendered with react-markdown/remark-gfm, including headings, emphasis, lists, tables and code. Raw HTML and Markdown image loads are disabled; local media uses scoped file cards. Historical wording stays intact. Creative instructions favor a concrete recommendation with brief-specific reasoning, visual motivation/pacing/setup/payoff, and concise shot tables where useful. Proposed timing remains a suggestion. Generic flattery and emoji are discouraged by default. These are instructions, not a measured claim that the model's creative reasoning improved.

## Deep Agents runtime update

The active Python video runtime now uses Deep Agents SDK with explicit LangChain model adapters. Node retains Project grants, credentials, SQLite and production tools. Real Project image assets, three-frame draft/MP4 inspection, up to three versioned render attempts/request, native request-scoped streaming/Stop and persisted reasoning effort are implemented. See [Python runtime guide](python-agent-runtime.md) for exact limits and trust boundaries. Verification and live-provider quality are separate claims. Research/Tavily and richer creative skill content remain subsequent work.

A complete video request uses one continuous timeline containing all scenes and one final MP4. A 2:07 brief is 127 seconds; the assistant must not split it into separate deliverables or render only the last draft segment. The existing renderer time budget still applies; length support is not a guarantee of model quality or job completion. Chat deduplicates registered file identities and suppresses a second inline player when a file is already represented by its final artifact. This also applies when displaying older saved messages.

## Cross-message editing

`trim_video` accepts an optional published video ID from `list_generated_files`. It can trim files created in earlier chat messages or before an app restart; omitting the ID selects the latest valid video in the same chat. The host revalidates the scoped file and measures its actual duration/audio with ffprobe. Each cut is a new MP4 and preserves the original.
